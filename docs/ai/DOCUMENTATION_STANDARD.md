# 📚 Velantrim Documentation Standard v1

`overview != current state != evidence != history`

- `STRUCTURAL_CHANGE`: review all maintained landing surfaces; update only affected representations.
- `STATE_CHANGE`: refresh stale high-level state implications.
- `EVIDENCE_ONLY`: update evidence/checkpoints without visual churn.

Visual roles: Tree = what exists; Mindmap = concept relations; ASCII = information/authority flow; Table = may/must-not boundary; Commentary = rationale.

Human entry: `PROJECT_OVERVIEW.md`. Machine state remains `project-state.json`.
